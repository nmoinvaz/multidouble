The build treats warnings as errors, so a proof left as `sorry` fails it. The kernel decides the longer evaluations,
on the rational mirrors of `Eval.lean`, and adds no axiom: `decide +kernel` reduces the comparison of two rationals to
`true`. Each theorem depends only on Lean's axioms `propext`, `Classical.choice` and `Quot.sound`, which
`#print axioms` shows. CI runs the build on every pull request that changes this folder
(`.github/workflows/lean.yml`). It does not build `Trig12.lean`, which is outside the default targets: run its line
above with `LEAN_NUM_THREADS=2`, as each of its last modules holds about 6 GB.

Lean is pinned to v4.34.1, and Mathlib and cslib to their v4.34.1 tags. FloatSpec pins v4.34.0-rc2, whose executables
abort at thread exit on macOS 27 ([lean4#15087](https://github.com/leanprover/lean4/issues/15087)).

`Controls/` is a second library, built with the proofs. `Controls/Axioms.lean` reads the axioms that Lean recorded for
every declaration of `ExpansionBounds`, the generated ones included, and fails the build on any but those three; its
own control is a theorem that rests on an axiom declared there, which the same test must report. The other files take
the kernel's checks with a wrong number, a wrong state or a hypothesis left out, and the kernel proves each such claim
